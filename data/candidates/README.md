# Discovery Candidates

This directory is the staging area for automated research.

A candidate is **not** a canonical MFTL fact record and must not be rendered as a verified public result.

Lifecycle:

`discovered → needs_sources → ready_for_record → merged`

A candidate can also become `rejected` when it is duplicate, unsourced, fabricated, or outside project scope.

Promotion requires:

1. duplicate check;
2. at least one meaningful source, with stronger claims requiring stronger/corroborating evidence;
3. extraction into the canonical myth-record schema;
4. claim-to-source linkage;
5. schema validation.
