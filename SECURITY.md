# Security and Integrity

MFTL treats **data integrity** as part of project security.

## Report privately when appropriate

Security-sensitive reports may include:

- dependency or supply-chain vulnerabilities;
- credential/token exposure;
- unsafe workflow configuration;
- injection or code-execution issues in the web application or tooling.

Do not place credentials, private keys, tokens, or sensitive personal information in a public issue.

## Research-integrity reports

The following should normally be reported through a GitHub issue using the Research / Data Record template:

- fabricated or broken citation;
- source misattribution;
- claim not supported by its source;
- duplicate identity;
- incorrect historical classification;
- assessment not traceable to evidence;
- accidental labeling of a living person or population;
- schema or provenance regression.

## Integrity principle

A failed claim should be corrected at the evidence layer. Do not weaken validation or provenance rules simply to make incorrect data pass.
